# 取り込みGAS「Booking-System」

予約台帳スプシに紐づいた（コンテナバインドの）GAS。5分ごとに動いて、Airbnb・Agoda・Expediaの予約を台帳に入れる。
Webアプリ（`booking/src/`）とは**別のGASプロジェクト**。ここにあるのは本番と同じコードの写し。

## やっていること（5分ごと）

1. 台帳の持ち主のGmailから、Airbnbの「予約確定」「キャンセル」「ご予約が変更されました」メールと、Agodaの「Agoda予約ID 〜 - 予約確定／キャンセル／変更」メール、Expediaの「Expedia - New／Cancelled／Modified Booking」メールを探す
2. 本文の決まった位置から文字を抜いて、「予約」タブに書く（AIは使わない）
3. 「Airbnb」タブにiCal URLを入れたリスティングは、Airbnbのカレンダーと日程を突き合わせる。変更メールには新しい日程が載らないので、日程はiCalから直す
4. 札を付け直す（下の表）
5. Googleカレンダー「小夜月 予約」に、キャンセル以外の予約を終日の予定で書く。色は Airbnb＝オレンジ、Agoda＝藤色、Expedia＝水色、楽天＝青、直販＝黄、札あり＝赤
6. 新しい予約と、新しく出た札をメールで知らせる。`SLACK_WEBHOOK_URL` があれば同じ文をSlackにも送る（[部屋未設定] [入湯税] [メールなし] は台帳に出すだけで通知しない）

## 台帳のタブ

| タブ | 中身 |
| --- | --- |
| 予約 | 1行1予約。列は `Code.js` の `RES_COLS`。Webアプリの手動入力もここの末尾に足される |
| 部屋 | 部屋・定員・状態（販売可／準備中／停止） |
| Airbnb | リスティングID → 部屋の紐付けと、iCal URL |
| Agoda | Agodaの部屋タイプ → 部屋の候補。新しいタイプはメールが来たときに自動で足される。「部屋」に1つ書けばその部屋、「302,月山」のように複数書けばその中から、空なら販売可の全部屋から、人数と空きを見て自動で決める（定員の小さい順）。空きがなければ [部屋未設定] |
| Expedia | Expediaの部屋タイプ → 部屋の候補。使い方はAgodaタブと同じ |
| ログ | 取り込んだメールの記録。1行目の「最終実行」の隣に最後に動いた時刻 |

`更新日時` `カレンダーID` `カレンダー同期` はこのGASが使う列。人もWebアプリも書き換えない（Webアプリの手動入力が `更新日時` を入れるのはOK）。

## 「要確認」の札

| 札 | 付く条件 | 消え方 |
| --- | --- | --- |
| [重複] | 同じ部屋・同じ夜にキャンセル以外の予約が2つ以上 | 毎回付け直す |
| [部屋未設定] | 部屋が空（Airbnbタブで紐付いていないリスティング） | 毎回付け直す |
| [準備中の部屋] | これからの予約で、部屋タブの状態が販売可でない | 毎回付け直す |
| [定員超え] | これからの予約で、大人＋子どもが定員より多い | 毎回付け直す |
| [入湯税] | 子どもがいる（子どもの課税は上山市に確認中。今は大人だけで計算） | 毎回付け直す |
| [変更] | 変更メールが来た | 人が消す |
| [人数要確認] | メールの人数欄が読めなかった | 人が消す |
| [iCalで日程変更] | iCalの日程がメールと違ったので直した | 人が消す |
| [iCalにない] | 前日以前に入った未来の予約がiCalから消えた（キャンセル疑い） | 人が消す |
| [メールなし] | iCalにだけある予約 | メールが届くと自動で消える |
| [Agoda要確認] | Agodaのメールで名前・人数・部屋タイプが読めなかった、2室以上の予約 | 人が消す |
| [Expedia要確認] | Expediaのメールで名前・人数・部屋タイプが読めなかった、2室以上の予約 | 人が消す |

入湯税は大人1人1泊300円。2026年4月1日より前の予約は150円。

## スクリプトプロパティ

公開リポジトリなので、アドレスやIDはコードに書かない。

| プロパティ | 中身 |
| --- | --- |
| `NOTIFY_TO` | 通知メールを足す宛先（カンマ区切り）。台帳の持ち主には何もしなくても送る |
| `SLACK_WEBHOOK_URL` | 通知メールと同じ文を送るSlackのIncoming Webhook。空ならSlackには送らない |
| `calendarId` | `setupCalendar` が自動で入れる。触らない |

iCal URLは「Airbnb」タブにだけある。リポジトリやドキュメントには書かない（空き状況と予約コードが外から見える）。

## 関数

| 関数 | いつ |
| --- | --- |
| `setup` | 最初の1回。タブを作り、過去1年分のメールを取り込み、5分ごとの自動実行を入れる |
| `run` | 自動で5分ごと。手で押してもいい |
| `setupCalendar` | カレンダー連携を足したときに1回 |
| `setupAgoda` | Agodaの取り込みを足したときに1回。「Agoda」タブを作り、媒体の選択肢にAgodaを足す（並べ替えはしないので、動いている台帳で押してよい） |
| `importPast` | 過去1年分のメールをさかのぼって取り込む（`run` は直近14日だけ）。Agodaを足したときなど。並べ替えはしない・通知は出さない・何度押してもいい |
| `useThisAccount` | 取り込みを、今エディタを開いているアカウントで動かす（そのアカウントのGmailを読む）。前のアカウントの自動実行は前のアカウントで消す。カレンダーは持ち主から共有しておく |
| `refreshAgoda` | Agodaの読み方を直したあとに1回。直近60日のAgodaのメールを読み直し、名前・人数・部屋タイプ・金額などを上書きする（手で選んだ部屋は残す） |
| `checkAgodaMail` | Agodaのメールが拾えないときの確認用。読んでいるGmailのアカウントと、Agodaらしいメールの差出人・件名・判定を実行ログに出す |
| `setupExpedia` | Expediaの取り込みを足したときに1回。「Expedia」タブを作り、媒体の選択肢にExpediaを足す |
| `checkExpediaMail` | Expediaのメールが拾えないときの確認用。差出人・件名・判定と、読み取った中身を実行ログに出す |
| `refreshExpedia` | Expediaの読み方を直したあとに1回。直近60日のExpediaのメールを読み直して上書きする（手で選んだ部屋は残す） |
| `showAgodaMail` | Agodaのメールで人数・部屋タイプが読めないときに。読めなかったメールの本文を実行ログに出す（最大3通。名前・電話が入るので外に貼らない） |
| `testSlack` | `SLACK_WEBHOOK_URL` を入れたあとに1回。Slackにテストの通知を送る |
| `dryRun` | 台帳に書かずに、直近60日のメール（Airbnb・Agoda・Expedia）の読み取り結果だけを実行ログに出す |

`setup` は「予約」タブをチェックイン順に並べ替える。行番号が変わるので、**Webアプリを使い始めたら押さない**。

## 本番への反映

台帳のスプシ →「拡張機能」→「Apps Script」→「コード.gs」に `Code.js` の中身を丸ごと貼って保存する。
5分ごとの実行は保存した最新のコードで動くので、デプロイは要らない。

テストは `booking/` で `npm test`（`test/booking-system*.test.mjs`）。メール本文は実物と同じ構造で、名前・予約コード・リスティングIDはダミー。

## 方針（2026-11-02 時点）

- 自動で取り込むのはAirbnb・Agoda（2026-11-11〜）・Expedia（2026-11-20〜）。予約が入ったときにほかの媒体の在庫を閉じるのは人が手でやる。「楽天を閉じて」「Airbnbを更新して」の通知は出していない
- 予約の正はスプシ。Googleカレンダーは写しで、カレンダー側で直しても台帳には戻らない

## Agodaの取り込み（2026-11-11〜）

- 件名「Agoda予約ID 1700000001 - 予約確定 Hotel ホテル所在国: Japan」で予約IDと種類（確定／キャンセル／変更）を決める。英語の件名（Agoda Booking ID）も読む
- 取り込みGASが読むのは、5分ごとの自動実行を入れたアカウントのGmailだけ。2026-11-12 に会社のアカウント（Agodaの通知が届く sayozuki.com）へ切り替えた（`useThisAccount`）。Airbnbの通知は個人のGmailに届くので、個人のGmailのフィルタで会社のアカウントへ自動転送する
- 送り主に `agoda` が入ったメールだけ読む。手で転送したメール（件名が「Fwd:」で、本文の転送元が agoda.com）も読む
- 本文はAgodaの予約確認書（HTMLメール）。`getPlainBody` では太字が `*…*`、表は見出しのセルが1行ずつ並んだあとに値のセルが並ぶ。読むもの：日程（Check-in / Check-out）、表の1行目（客室タイプ・部屋数・宿泊可能人数）、予約者情報の「氏名」「電話番号」、表示販売料金（ゲスト支払額）、卸値（受取額）、特別なリクエスト（メモ）。実物の形は `test/booking-system-agoda.test.mjs` の `REAL_JA`（名前・番号はダミー）
- 本文はHTMLから、セルごとに改行を入れて読む（`getPlainBody` だとセルがつながって「…Non Smoking12 Adults0」になり、人数・部屋タイプが読めなかった。2026-11-20 に修正）。Expediaも同じ
- 部屋は人数が分かってから決める。人数が空のうちは [部屋未設定]（人数が分からない）のまま。自動で決めた部屋が、あとで分かった人数に足りなければ選び直す（人が選んだ部屋・タブで1部屋に紐付けた部屋は触らない）
- 日程が読めない予約確定は台帳に入れず、「要手入力」の通知メールにGmailのリンクを付けて出す
- 予約番号はAgodaの予約ID（数字）。「リスティングID」列にはAgodaの部屋タイプ名が入る
- 現地払いの予約は「支払い状況」を「未収」、それ以外は「媒体で決済済」にする
- ホテル向けの管理画面（YCS）にはAirbnbのようなiCalがないので、取り込みはメールだけ

## Expediaの取り込み（2026-11-20〜）

- 件名「Expedia - New Booking - Arriving on 21 Nov 2026」で種類を決める（New＝確定、Cancelled＝キャンセル、Modified＝変更）。Hotels.com・Vrbo 経由の予約も件名は Expedia
- 送り主に `expedia` が入ったメールだけ読む。手で転送したメール（Fwd:）も読む
- 予約番号は本文の Reservation ID（数字）。「リスティングID」列には Room Type Name（Room Type Code が「RoomCode」のような中身のない値のことがあるので名前を使う）
- 読むもの：Check-In／Check-Out、Adults、Kids/Ages、Guest（名前と次の行の電話）、Room Type Name、Special Request、合計金額
- 「Hotel Collects Payment from Guest」（現地払い）は「支払い状況」を「未収」、Expedia Collect は「媒体で決済済」
- 部屋は「Expedia」タブで紐付ける。空なら人数と空きから自動で決める（Agodaと同じ）
- 新しい予約の通知に「Partner Centralで確認番号を入れて」を添える（Expediaが予約ごとに求めてくる。台帳の予約番号を入れればいい）
- 実物（2026-11-19 受信）で確かめた形：日程・人数は「Check-In Check-Out Adults Kids/Ages Room Nights」の見出しの行のあとに値の行（Kids/Ages は「1 /12」＝子ども1人・12歳）。名前は「Guest:」の次の行、電話はその下の数字だけの行。合計は「Total:」。メールのリンクは計測用URLを経由するので、予約画面のURLは予約番号から組み立てる
- 読めない欄があれば [Expedia要確認] が付くので、`checkExpediaMail` の実行ログを見て直す
