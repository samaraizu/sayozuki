# 取り込みGAS「Booking-System」

予約台帳スプシに紐づいた（コンテナバインドの）GAS。5分ごとに動いて、Airbnb・Agodaの予約を台帳に入れる。
Webアプリ（`booking/src/`）とは**別のGASプロジェクト**。ここにあるのは本番と同じコードの写し。

## やっていること（5分ごと）

1. 台帳の持ち主のGmailから、Airbnbの「予約確定」「キャンセル」「ご予約が変更されました」メールと、Agodaの「Agoda予約ID 〜 - 予約確定／キャンセル／変更」メールを探す
2. 本文の決まった位置から文字を抜いて、「予約」タブに書く（AIは使わない）
3. 「Airbnb」タブにiCal URLを入れたリスティングは、Airbnbのカレンダーと日程を突き合わせる。変更メールには新しい日程が載らないので、日程はiCalから直す
4. 札を付け直す（下の表）
5. Googleカレンダー「小夜月 予約」に、キャンセル以外の予約を終日の予定で書く。色は Airbnb＝オレンジ、Agoda＝藤色、楽天＝青、直販＝黄、札あり＝赤
6. 新しい予約と、新しく出た札をメールで知らせる（[部屋未設定] [入湯税] [メールなし] は台帳に出すだけで通知しない）

## 台帳のタブ

| タブ | 中身 |
| --- | --- |
| 予約 | 1行1予約。列は `Code.js` の `RES_COLS`。Webアプリの手動入力もここの末尾に足される |
| 部屋 | 部屋・定員・状態（販売可／準備中／停止） |
| Airbnb | リスティングID → 部屋の紐付けと、iCal URL |
| Agoda | Agodaの部屋タイプ → 部屋の紐付け。新しいタイプはメールが来たときに自動で足される。1タイプが複数の部屋にまたがるなら「部屋」は空のままにし、予約ごとに台帳で選ぶ |
| ログ | 取り込んだメールの記録。1行目の「最終実行」の隣に最後に動いた時刻 |

`更新日時` `カレンダーID` `カレンダー同期` はこのGASが使う列。人もWebアプリも書き換えない（Webアプリの手動入力が `更新日時` を入れるのはOK）。

## 「要確認」の札

| 札 | 付く条件 | 消え方 |
| --- | --- | --- |
| [重複] | 同じ部屋・同じ夜にキャンセル以外の予約が2つ以上 | 毎回付け直す |
| [部屋未設定] | 部屋が空（Airbnbタブで紐付いていないリスティング） | 毎回付け直す |
| [準備中の部屋] | これからの予約で、部屋タブの状態が販売可でない | 毎回付け直す |
| [定員超え] | これからの予約で、大人＋子どもが定員より多い | 毎回付け直す |
| [入湯税] | 子どもがいる（子どもの課税は上山市に確認中。今は大人だけで計算） | 毎回付け直す |
| [変更] | 変更メールが来た | 人が消す |
| [人数要確認] | メールの人数欄が読めなかった | 人が消す |
| [iCalで日程変更] | iCalの日程がメールと違ったので直した | 人が消す |
| [iCalにない] | 前日以前に入った未来の予約がiCalから消えた（キャンセル疑い） | 人が消す |
| [メールなし] | iCalにだけある予約 | メールが届くと自動で消える |
| [Agoda要確認] | Agodaのメールで名前・人数・部屋タイプが読めなかった、2室以上の予約 | 人が消す |

入湯税は大人1人1泊300円。2026年4月1日より前の予約は150円。

## スクリプトプロパティ

公開リポジトリなので、アドレスやIDはコードに書かない。

| プロパティ | 中身 |
| --- | --- |
| `NOTIFY_TO` | 通知メールを足す宛先（カンマ区切り）。台帳の持ち主には何もしなくても送る |
| `calendarId` | `setupCalendar` が自動で入れる。触らない |

iCal URLは「Airbnb」タブにだけある。リポジトリやドキュメントには書かない（空き状況と予約コードが外から見える）。

## 関数

| 関数 | いつ |
| --- | --- |
| `setup` | 最初の1回。タブを作り、過去1年分のメールを取り込み、5分ごとの自動実行を入れる |
| `run` | 自動で5分ごと。手で押してもいい |
| `setupCalendar` | カレンダー連携を足したときに1回 |
| `setupAgoda` | Agodaの取り込みを足したときに1回。「Agoda」タブを作り、媒体の選択肢にAgodaを足す（並べ替えはしないので、動いている台帳で押してよい） |
| `importPast` | 過去1年分のメールをさかのぼって取り込む（`run` は直近14日だけ）。Agodaを足したときなど。並べ替えはしない・通知は出さない・何度押してもいい |
| `checkAgodaMail` | Agodaのメールが拾えないときの確認用。読んでいるGmailのアカウントと、Agodaらしいメールの差出人・件名・判定を実行ログに出す |
| `dryRun` | 台帳に書かずに、直近60日のメール（Airbnb・Agoda）の読み取り結果だけを実行ログに出す |

`setup` は「予約」タブをチェックイン順に並べ替える。行番号が変わるので、**Webアプリを使い始めたら押さない**。

## 本番への反映

台帳のスプシ →「拡張機能」→「Apps Script」→「コード.gs」に `Code.js` の中身を丸ごと貼って保存する。
5分ごとの実行は保存した最新のコードで動くので、デプロイは要らない。

テストは `booking/` で `npm test`（`test/booking-system*.test.mjs`）。メール本文は実物と同じ構造で、名前・予約コード・リスティングIDはダミー。

## 方針（2026-11-02 時点）

- 自動で取り込むのはAirbnbとAgoda（Agodaは2026-11-11〜）。予約が入ったときにほかの媒体の在庫を閉じるのは人が手でやる。「楽天を閉じて」「Airbnbを更新して」の通知は出していない
- 予約の正はスプシ。Googleカレンダーは写しで、カレンダー側で直しても台帳には戻らない

## Agodaの取り込み（2026-11-11〜）

- 件名「Agoda予約ID 1796010901 - 予約確定 Hotel ホテル所在国: Japan」で予約IDと種類（確定／キャンセル／変更）を決める。英語の件名（Agoda Booking ID）も読む
- 取り込みGASが読むのは、5分ごとの自動実行を入れたアカウントのGmail（Airbnbの通知が届く個人のGmail）。Agodaの通知は会社のアドレス（sayozuki.com）に届くので、そちらのGmailのフィルタで、差出人 agoda.com・件名に Agoda のメールを個人のGmailへ自動転送している
- 送り主に `agoda` が入ったメールだけ読む。手で転送したメール（件名が「Fwd:」で、本文の転送元が agoda.com）も読む
- 本文は「チェックイン」「宿泊者名」「部屋タイプ」「大人」「販売料金」「ネット料金」などの見出しの近くを探して読む。**本文は実物を見ずに作った**ので、最初のAgodaの予約が来たら `dryRun` の結果を見て、読めていない欄があれば実物（名前・番号はダミーに）を `test/booking-system-agoda.test.mjs` に入れて直す
- 日程が読めない予約確定は台帳に入れず、「要手入力」の通知メールにGmailのリンクを付けて出す
- 予約番号はAgodaの予約ID（数字）。「リスティングID」列にはAgodaの部屋タイプ名が入る
- 現地払いの予約は「支払い状況」を「未収」、それ以外は「媒体で決済済」にする
- ホテル向けの管理画面（YCS）にはAirbnbのようなiCalがないので、取り込みはメールだけ
